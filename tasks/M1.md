# M1 — Parser core

Cut from `spec/SPEC.md` §5, §18, §19 plus `research/sch-format.md` (R1) and
`research/sexpr-strategy.md` (R2). Decisions from `DECISIONS-R6.md`. Code
standards and the gate list come from `ENGINEERING.md`.

**Goal of M1.** A token-preserving syntax tree and an exact re-emitter for
`.kicad_sch`, `.kicad_sym` and `.kicad_pro`, with byte-identical round trip
for KiCad-authored input and semantic round trip for everything else gating
merges, the in-repo fixture corpus bootstrapped, and
`cargo xtask corpus` fetching KiCad's GPL demo/`qa` files into `target/` for the
external gates.

**Rules for this milestone.**

- Constitution §11: every task below names an executable completion check. A
  task is not done until that exact command passes.
- `ENGINEERING.md`: **`cargo xtask check` must also pass at every commit**, not
  only at milestone end. The per-task check below is in addition to it, never
  instead of it.
- `ENGINEERING.md` "Testing pyramid": write the test before the implementation.
- Tasks are ordered; each depends only on those above it. Where two are
  independent that is noted.
- No command surface, no geometry, no lint. M1 ends at "parse and re-emit
  faithfully", exposing the API M2 consumes.
- `cargo test` (no features) must stay hermetic: no network, no `kicad-cli`, no
  GPL files. External-corpus and oracle tests are feature- or env-gated.

## Resolved — decisions taken, recorded here so they are not re-litigated

**B1 — writing `.kicad_pro`. Resolved: read-only in v1.**

T18 measured 37 project files. 34 round-trip byte-identically through an
order-preserving JSON reader; key order and indentation always match. The other
3 differ in one way only, and **the values are identical doubles — only the text
differs**: KiCad prints the full expansion, `0.049999999999999996`, where a
shortest-round-trip printer emits `0.05`.

Ruling: **(b) now, (c) when a write path first exists.** No v1 command writes a
project file, so (b) costs nothing. When one is needed, (c) is built the same
way the s-expression side is — **preserve the source text of every value kicli
did not modify, and print the values kicli does write with a KiCad-matching
float printer**. Byte identity then falls out rather than being traded away.
Reformat-and-flag is rejected: a file that opens cleanly with one number reading
differently is the failure this tool exists to prevent. Recorded in
`spec/SPEC.md` §5.5.

**B2 — the licence gate and dev-dependencies. Resolved: dev-dependencies are
exempt.**

The allowlist governs the shipped artefact — normal and build dependencies.
Dev-dependencies are exempt, because a test helper is not distributed.
Advisories still cover everything. Both halves verified on this workspace: an
MPL-2.0 crate is rejected as a normal dependency and passes as a
dev-dependency, and a crate with an open RUSTSEC advisory fails as a
dev-dependency. `ENGINEERING.md` now says so, and the split is what cargo-deny
already does rather than a concession to it.

**B3 — the fuzz harness. Resolved: deferred, post-v1 backlog.**

No nightly toolchain. Fuzzing becomes optional, local-only, and **never a merge
gate**. The property it would defend — arbitrary bytes produce an error or a
tree, never a panic — is held on stable by two property tests. A fuzzer would
add coverage-guided search and a persistent corpus. Recorded in `spec/SPEC.md`
§17.

Nothing in M1 is blocked.

## Tasks

### T1 — Scaffolding and the gate harness (task zero) ✅

Everything else depends on this. It ships no kicli logic; it makes "done"
mechanically checkable for every task that follows.

**Workspace.** A virtual manifest with three members, per `ENGINEERING.md`
"Structure":

| Crate | Holds | Depends on |
|---|---|---|
| `crates/kicli-sexpr` | tokens, the token-preserving tree, the `Prettify` port | nothing of ours |
| `crates/kicli` | modules `model`, `geometry`, `connectivity`, `lint`, `render`, `libraries`, `pcb`, `cli`, plus a thin binary | `kicli-sexpr` |
| `xtask` | workspace automation | nothing |

`kicli-sexpr` knows nothing about schematics. `cli` depends on the other
modules; nothing depends on `cli`. **The crate boundary enforces the dependency
direction — do not merge the crates for convenience.** Each module and crate
carries a `//!` paragraph stating its single responsibility, in Simplified
Technical English.

**Lints.** In **both** `lib.rs` files: `#![deny(missing_docs)]`,
`#![deny(unsafe_code)]`, `#![warn(clippy::pedantic)]`. The binary and `xtask`
carry the same two denials.

**Tool config.** `rustfmt.toml` (stable options only), `clippy.toml`
(`too-many-lines-threshold`, and `doc-valid-idents` so "KiCad" needs no
backticks), `deny.toml` allowing MIT/Apache-2.0/BSD only — **MPL-2.0 and GPL
must be denied** (Constitution §9, Q8). Dual `LICENSE-MIT` / `LICENSE-APACHE`.
`rust-toolchain.toml` pinning stable with `rustfmt` and `clippy`, so a fresh
clone can run the gates without extra setup.

**Gate harness.** `.cargo/config.toml` aliases `xtask` to
`run --package xtask --`. `cargo xtask check` runs all five gates from
`ENGINEERING.md` in order — `fmt --check`, `clippy --all-targets --all-features
-- -D warnings`, `test`, `doc --no-deps` (with `RUSTDOCFLAGS=-D warnings`, so
"builds clean" is testable), `deny check` — and does **not** stop at the first
failure, so one run reports every problem. It prints a pass/FAIL summary and an
install hint for any gate whose tool is missing. `xtask` uses the standard
library only: it must run before anything else builds.

- **Check:** `cargo xtask check` exits 0 on the empty skeleton, with all five
  gates reporting `pass`.
- **Check:** `cargo xtask` with no task exits 2 and prints the task list.
- **Check:** `cargo deny check licenses` fails when an MPL-2.0 crate is
  temporarily added to `crates/kicli/Cargo.toml`. Verified with `option-ext`
  0.2.0 (MPL-2.0): `licenses FAILED`, exit 4.

**Known limitation, for T22.** The same MPL-2.0 crate added as a
**dev-dependency** passes. cargo-deny 0.20.2 prunes dev-dependency edges from
the licence graph, and `[graph] exclude-dev = false` does not change it. The
gate therefore covers the shipped artifact, not the test-only dependency tree.
That is defensible — an MPL test helper does not contaminate an MIT/Apache
binary — but `ENGINEERING.md` does not qualify its allowlist. Re-verify when the
first real dev-dependency lands at T22, and decide then whether to add a
separate check.

### T3 — Byte lexer ✅

T3 to T14 land in the **`kicli-sexpr`** crate. That crate must gain no knowledge
of schematics: version gating (T17) is the first task that needs schematic
meaning, so it lives in `kicli` and reads the version stamp as a plain token.

Five token classes over `&[u8]`, UTF-8 validated once up front: `LParen`,
`RParen`, `QuotedString` (`'"' ( '\\' . | [^"\\] )* '"'`), `BareAtom`
(`[^ \t\r\n()"]+`), `Comment` (`#` as first non-blank on a line, mirroring
`dsnlexer.cpp:575`). **No number classification and no escape processing at lex
time** — both are queries on the node, so `41.91` can never come back as
`41.910000000000004` (`sexpr-strategy.md` §4.1).

- **Check:** `cargo test lexer_classifies_tokens` — unit tests per class plus a
  table test asserting that re-concatenating every token's source span
  reproduces the input minus inter-token whitespace, for every fixture in T2.

### T4 — Arena tree and `Doc` ✅

`Doc { src, nodes: Vec<Node>, root, mode, canonical }` with
`Node::{ List { head, children, span }, Atom { kind, span, edited }, Comment }`,
index-based `NodeId` handles. The span into the original source is the source of
truth for unedited atoms; `edited: Option<Box<str>>` is `None` until kicli
changes a value. This makes "never rewrite a token we did not modify" structural
rather than a convention (`sexpr-strategy.md` §4.2). Memoise the head atom so
`list.head_is("symbol")` is O(1).

- **Check:** `cargo test atom_spans_match_source` — for every fixture, walk the
  tree and assert every atom's `&src[span]` is byte-equal to what the lexer
  produced, and that node count matches the token count.

### T5 — `flatten` ✅

Delete every whitespace run outside quotes, replacing it with a single space.
Destroys layout, preserves tokens. This is the input to the prettifier identity
test.

- **Check:** `cargo test flatten_preserves_tokens` — `lex(flatten(f))` yields
  the same token list as `lex(f)` for every fixture, with quote-aware handling
  verified by `escapes.kicad_sch`.

### T6 — `Prettify` port, NORMAL mode ✅

Literal port of `KICAD_FORMAT::Prettify` (`common/io/kicad/kicad_io_utils.cpp:97-339`),
including the four rules the doc comment omits: `(xy …)` run-packing to
`xySpecialCaseColumnLimit = 99`; the `consecutiveTokenWrapThreshold = 72` long-token
wrap; backslash-parity quote tracking so `\\"` is not read as an escaped quote;
exactly one trailing `\n` (`sch-format.md` §2.1).

- **Check:** `cargo test prettify_reproduces_kicad_layout` —
  `prettify(flatten(f)) == f` for every fixture in T2 declared
  canonical+NORMAL, and `prettify(prettify(x)) == prettify(x)` (idempotence)
  for all of them.

### T9 — Prettifier modes and detection ✅

Add `COMPACT_TEXT_PROPERTIES` (keeps `font stroke fill teardrop offset rotate

- **Check:** `cargo test format_mode_is_detected_and_preserved` —

  round-trips; the legacy one detects non-canonical.

### T10 — Fixed-point integer formatter, with the `{:.10g}` equivalence proof ✅

`fmt_iu(v: i32) -> String`: format the integer IU as fixed-point mm with 4
fractional digits, strip trailing zeros then a trailing `.`. This avoids float
formatting entirely and is claimed identical to KiCad's `{:.10g}` output for all
`int32` inputs (`sch-format.md` §2.3). The claim must be **proved, not
asserted.** Also `fmt_angle` for `{:.10g}` on degrees, and the separate paths for
`(color …)` alpha and `(scale …)` (`{:g}`).

- **Check:** `cargo test --release fmt_iu_matches_kicad_for_all_i32` — a
  reference implementation of `{:.10g}` (or a committed table generated from
  C++ `fmt`) compared against `fmt_iu` across the **full `i32` range** in
  release mode, plus the `|value| <= 0.0001` branch. Test fails on the first
  divergence and prints it.
- **Check:** `cargo test --features corpus fmt_iu_reproduces_corpus_numbers` —
  every numeric atom in the external corpus parses to an `i32` IU and
  re-formats to its exact original bytes.

### T11 — String quoting and unquoting ✅

Escape exactly four characters — `\n`, `\r`, `\\`, `\"` — and nothing else. No
`\t`, no `\uXXXX`, no octal; UTF-8, tabs, and parens inside strings are written
raw (`richio.cpp:468`, `sch-format.md` §2.2). User data is always quoted; keyword
tokens are always bare.

- **Check:** `cargo test quoting_escapes_four_characters` — round-trip property
  over nasty strings (embedded quotes, backslashes, newlines, UTF-8, empty,
  `~`, `#`-leading, a literal tab), plus a byte assertion against the
  `text_box` line in `escapes.kicad_sch`.

### T12 — Emitter ✅

Two stages mirroring KiCad: walk the tree to a flat token stream with single
spaces, then prettify in the detected mode. Emission prefers `edited`, else
`&src[span]`.

- **Check:** `cargo test emit_without_edits_is_identity` — for every canonical
  fixture, `emit(parse(f)) == f` bytewise with no edits applied.

### T13 — Byte-identical round trip for KiCad-authored input ✅

Promote T12's property to a named merge gate over both corpora
(`spec/SPEC.md` §5.3).

- **Check:** `cargo test emit_reproduces_input_bytes` (fixtures) and `cargo
  test --features corpus emit_reproduces_input_bytes_corpus` — both must be 100
  % over files the manifest/corpus marks canonical. Non-canonical files are

### T14 — Semantic round trip for every input ✅

`parse(emit(parse(f))) ≡ parse(f)` — structural equality of the tree modulo
whitespace and atom spans. This is the property that must hold for *all* input,
including non-canonical and pre-v10 files, and is the honest floor Constitution
§1 describes.

- **Check:** `cargo test reparse_preserves_tree` and `cargo test --features
  corpus reparse_preserves_tree_corpus` — 100 % including
  `noncanonical.kicad_sch`, `v9_legacy.kicad_sch`, and every `qa/data` file
  (which are deliberately pathological and include older format versions).

### T15 — An edit changes only its own region ✅

Provide `Doc::set_atom(NodeId, &str)` plus a `line_diff` helper, and assert an
edit touches only its own region. The commands come in M3; the harness and the
property are M1's, because it is the property most likely to regress silently
(`sexpr-strategy.md` §5 L3).

- **Check:** `cargo test edit_changes_only_its_own_lines` — editing one
  `property` value atom in `all_items.kicad_sch` changes ≤ 3 lines of output;
  editing one `(xy …)` coordinate changes ≤ 1 line; the rest of the file is
  byte-identical.

### T16 — Write policy: canonicality, comments, version ceiling ✅

Implement the §5.4 table: non-canonical input is reformatted with
`"reformatted": true` and a reason; `#` comments cause a **refusal to write**
unless `--allow-comment-loss`; a version stamp above `formats.max_schematic_version`
(default `20260306`) causes a refusal. Refusals are exit 4 with structured
errors (`spec/SPEC.md` §6.1).

- **Check:** `cargo test write_reports_reformatting_and_refuses_loss` — four
  cases: `noncanonical` writes and reports `reformatted: true`; `commented`
  refuses by default and succeeds with the flag (and the comment is gone);
  `future_version` refuses and succeeds with the config override; a canonical
  file reports `reformatted: false`.

### T17 — Version-gated semantics ✅

Key `~`-means-empty (below stamp `20250318`) and `hide` placement (inside

## Milestone exit criteria

M1 is complete when all of the following pass on a clean checkout:

```sh
cargo build --workspace
cargo deny check licenses
cargo test                                   # hermetic: fixtures only
cargo xtask corpus
cargo test --features corpus                 # includes 115/115 prettifier identity
```

and `cargo test --features corpus emit_reproduces_input_bytes_corpus reparse_preserves_tree_corpus`
reports 100 % byte identity on canonical files and 100 % semantic identity on
all files.

| Gate | Result |
|---|---|
| demo schematics reproduced from tokens alone | 115/115 |
