# M2 — Geometry and read

Cut from `spec/SPEC.md` §5.6, §6, §7, §8, §14, §15, §18, §19 plus
`research/geometry.md` (R7), `research/representation.md` (R10) and
`research/kicad-cli.md` (R3). Code standards and the gate list come from
`ENGINEERING.md`. The API M1 froze (T25) is the floor everything here builds on.

**Goal of M2.** Integer geometry that agrees with KiCad — the symbol transform,
pin positions, text extents and bounding boxes — a connectivity extractor whose
net partition equals `kicad-cli`'s, the three compact views inside their byte
budgets, and the first two real commands, `project info` and `project check`.

**Rules for this milestone.**

- Constitution §11: every task below names an executable completion check. A
  task is not done until that exact command passes.
- `ENGINEERING.md`: **`cargo xtask check` must also pass at every commit**, not
  only at milestone end. The per-task check below is in addition to it, never
  instead of it.
- `ENGINEERING.md` "Testing pyramid": write the test before the implementation.
- `cargo test` (no features) stays hermetic: no network, no `kicad-cli`, no
  fetched corpus. Oracle outputs are committed as goldens; regenerating them is
  a separate env-gated test.
- Tasks are ordered. Each depends only on those above it. Lanes are marked in
  the phase headers and are the unit of parallel work.
- No mutation, no lint, no score, no render, no vendoring, no routing. M2 reads.
  The one write path in the milestone is the snapshot cache under `.kicli/`.
- Constitution §8 and §10: the milestone adds commands, so `AGENT.md` lands in
  the same milestone (T25), not later.

## Resolved — decisions taken, recorded here so they are not re-litigated

**B1 — the modules SPEC requires but `ENGINEERING.md` did not name. Resolved:
add them, and amend the list.**

`spec/SPEC.md` §7 makes representations a concern distinct from rendering
(§12), and §14.1 requires that **all** external KiCad binary invocations go
through **one** module. Neither fits the eight modules `ENGINEERING.md` listed,
and neither can be folded into an existing one: views in `cli` would make
`model` depend on `cli` when M3 mutations echo a delta fragment, views in
`render` would merge the truth an agent acts on with a passive picture, and the
invocation module in `cli` would be unreachable from `lint` and `render`.

Ruling: `kicli` gains **`view`** and **`kicad`** — the second named for what it
owns, every call to an external KiCad binary, rather than a vague `tools`.
`ENGINEERING.md`'s list is amended in the same commit, and it now says plainly
that the list is not closed: a later milestone may add a module by stating the
concern and keeping the dependency direction.

**R1 — text metrics. Resolved: port KiCad's own logic; measure to check it.**

The risk was that `kicad-cli.md` §5.5's additive model
(`textLength(s) = Σ advance(c) + 3·penWidth`) and `geometry.md` §5.1's
`INTER_CHAR = 0.2` term might not reconcile. The GPL-3.0-or-later licence
removes the reason the model was ever fitted from the outside: **T8 ports
KiCad's measurement logic from source** — the stroke-font advance loop
(`common/font/stroke_font.cpp`), `StringBoundaryLimits`
(`common/font/font.cpp`), the pen-width derivation (`common/gr_text.cpp`) and
`GetTextBox` (`common/eda_text.cpp`) — with glyph advances derived from KiCad's
Newstroke data. A port is exact by construction; a fitted table is exact only
where it was sampled.

**The SVG measurement is kept as the oracle, not the source.** The calibration
sheet still runs through `kicad-cli`, and the port must reproduce its
`textLength` values. Empirical calibration — fit the residual, fold it into the
table, pin the fit with a test — is now the **fallback**, used only if the port
and the oracle disagree by a stable linear term. T8 parks only if a residual
appears that is neither reconciled by the port nor stable.

Licence hygiene, which is now a live obligation rather than a bar: Newstroke is
GPL-2.0-or-later and KiCad's own sources are GPL-3.0-or-later. Every ported
function and the derived advance table carry a comment naming the source file
and its copyright holder. Constitution §9 permits the derivation; it does not
excuse dropping the notice.

Exactness is confirmed again later, through IPC `GetTextExtents`
(`DECISIONS-R6.md` Q10). M2 needs boxes good enough for lint geometry.

**R2 — the large-sheet budgets. Resolved: split the coverage, gate both halves.**

The ceilings in `spec/SPEC.md` §7.4 are set on 130–234 symbol sheets, which
exist only in KiCad's demo corpus, fetched into `target/`. The hermetic run
gates a smaller ceiling **and** the compression ratio against the source file,
so a regression that doubles the output fails without the corpus. The corpus run
validates the published ceilings. Both are named in T23. This is a coverage
split, not a weakened gate.

Nothing in M2 is blocked.

### T2 — Typed item model over the tree

`model` gains the objects the rest of kicli works with, read-only: symbol, field
(`property` on symbol, sheet, global label, netclass flag), wire, bus, bus
entry, junction, no-connect, local/global/hierarchical label, netclass flag,
text, text box, graphic shape, image, sheet, sheet pin, table. Each carries its
UUID and the `NodeId` it came from, so a later mutation edits the tree and not a
copy. Unknown top-level tokens parse into an explicit `Unknown` variant rather
than being dropped — the parser accepts more tokens than the corpus exercises
(`sch-format.md` §1).

Newtypes, not primitives: `Iu(i32)`, `Point`, `Uuid`, `Refdes`, `LibId`,
`SheetPath`. The `~`-means-empty and `hide`-placement rules come from
`model::version`, which M1 already ships.

- **Check:** `cargo test items_parse_from_every_top_level_token` — every
  top-level token in `all_items.kicad_sch` and in the demo corpus maps to a
  typed item or to `Unknown`; the typed item count equals the tree's top-level
  list count; no item loses its UUID.

### T3 — Project and hierarchy loader

Load a root `.kicad_sch`, follow every `sheet` item's `Sheetfile` to its child
file, and build the sheet tree. Produce sheet paths in KiCad's form,
`"/" + rootScreenUuid + ("/" + sheetItemUuid)*` (`sch-format.md` §3.6), page
numbers from `sheet_instances`, and the per-path reference for every symbol read
from `instances`, **not** from the cached `Reference` property
(`spec/SPEC.md` §5.6). A sheet file placed twice is loaded once and appears at
two paths. Detect and report a cycle rather than recursing. Flat
multi-top-level hierarchies are readable, and `--sheet` addressing errors
clearly on them (`spec/SPEC.md` §5.7).

- **Check:** `cargo test sheet_paths_carry_their_own_references` — on
  `sch/multi_instance/`, the loader yields two sheet paths for the child sheet
  and the doubly-instantiated symbol reports `RV201` on one path and `RV301` on
  the other; on `sch/nets/`, the child sheet appears twice with distinct paths.
- **Check:** `cargo test sheet_cycle_is_reported_not_recursed` — a fixture whose
  child names its parent produces a typed error, not a stack overflow.

Read the project-local config of `spec/SPEC.md` §15. **Unknown keys are an

## Phase 1 — pin geometry (Lane A only; Lanes B, C, D wait on T7)

Pin positions are the input to connectivity and to both geometric views, so this
phase is a single lane and nothing runs beside it.

### T5 — The symbol transform

The 2×2 integer matrix of `geometry.md` §2. Build it from `(at … rot)`, then
compose `(mirror x|y)` **in file order**, using KiCad's row-major member naming
`(x1,y1),(x2,y2)` — transposing it silently swaps 90° and 270°, which is the
classic third-party bug. The group has exactly 8 elements; 180 and 270 with a
mirror reduce to entries already in the table. Normalise to the `(rot, mirror)`
pair KiCad itself would write.

- **Check:** `cargo test orientation_group_has_eight_elements` — all
  `(rot, mirror)` inputs map onto the 8-row table of `geometry.md` §2.3;
  `to_file(from_file(r, m))` is a fixed point for every input; composing any two
  elements lands inside the group; the matrix is asserted row-major against the
  table, with a case that fails if it is transposed.

### T6 — Library symbol resolution and pin selection

Resolve a placed symbol to its `lib_symbols` entry by `(lib_name …)` when
present and `lib_id` otherwise — keying by `lib_id` alone mis-resolves symbols
edited in place (`sch-format.md` §3.4). Select the child symbols whose
`NAME_<unit>_<bodyStyle>` suffix matches the instance's `(unit N)` and
`(body_style N)`, **plus** the unit-0 and body-style-0 pseudo-units
(`geometry.md` §3.2). Negate Y on every library coordinate at read time
(`geometry.md` §1). Honour instance-side `(alternate …)` on a pin.

- **Check:** `cargo test unit_and_body_style_select_pins` — a multi-unit
  fixture symbol exposes only its own unit's pins plus the common ones;
  `lib_name_redirect.kicad_sch` resolves through `lib_name` and not `lib_id`;
  library Y coordinates come back negated exactly once.

### T7 — Pin positions, verified against KiCad (permanent gate)

`abs_pin = symbol.at + M · (lib_pin.x, −lib_pin.y)` (`geometry.md` §3.1), in
integer IU throughout. Resolve pin direction through the transform too, since
the router and the escape rules need it in M4.

This is the **16-orientation pin fixture** named in `spec/SPEC.md` §18.

- **Check:** `cargo test pin_positions_match_kicad` — all 16 rows of
  `orientations.expected` match exactly, and all rows of `asymmetric.expected`
  match exactly, compared in integer IU with no tolerance.
- **Check:** `cargo test erc_json_coordinates_are_a_hundred_times_small` — the
  canary of `spec/SPEC.md` §14.2, asserted here because the fixture is here:
  `json.pos × 100 == text.pos` exactly on the committed oracles. The assertion
  **expects the bug**, so it fails loudly the day KiCad fixes it. The comparison
  site carries a comment naming `eeschema/erc/erc_report.cpp:161`.

### T8 — Glyph advances, ported from KiCad and checked against it (Lane A)

Port KiCad's own stroke-font metrics rather than fitting them from outside, per
`spec/SPEC.md` §8 as amended. The advance loop is
`STROKE_FONT::GetTextAsGlyphs` (`common/font/stroke_font.cpp:203-292`), the
string extents are `FONT::StringBoundaryLimits` (`common/font/font.cpp:451-478`)
with its `INTER_CHAR = 0.2` term, and the pen width comes from
`common/gr_text.cpp:35-68`. Glyph advances are derived from KiCad's Newstroke
data (`common/newstroke_font.cpp`).

`cargo xtask text-metrics` reads the Newstroke source from the corpus clone at
its pinned tag, computes the per-glyph advance, and writes
`crates/kicli/src/geometry/advances.table` — committed, so `cargo test` needs
neither KiCad nor the network. The table's header records the KiCad tag it came
from, **and Newstroke's copyright notice and GPL-2.0-or-later terms**; the
ported functions carry a comment naming their source file. Constitution §9
permits the derivation, and preserving the notice is part of accepting it.

`--verify` re-derives and diffs, so a KiCad upgrade that changes a glyph is
caught rather than assumed away.

The SVG measurement of `kicad-cli.md` §5.5 becomes the **oracle**: export
`calibration.kicad_sch`, read each item's `textLength`, and assert the port
reproduces it. If the two disagree, apply the fallback of R1 — fit the residual,
fold a stable linear term into the table, pin the fit with a test — and record
what happened in `research/notes/`. Park only on a residual that is neither
reconciled nor stable.

- **Check:** `cargo xtask text-metrics --verify` — re-derives the table from the
  pinned KiCad source and asserts the committed bytes are unchanged; exits with
  a clear message when the corpus is absent.
- **Check:** `cargo test advances_cover_printable_ascii` — the table has an
  entry for every printable ASCII code point, every advance is positive, the
  substitution glyph for unknown code points is `?`
  (`stroke_font.cpp:262-266`), and the table's provenance header names the tag
  and carries the upstream notice.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test advances_reproduce_kicad_svg`
  — for every item in `calibration.kicad_sch`, the ported computation matches
  KiCad's own `textLength`. The test prints the largest residual, so a drift
  that stays inside tolerance is still visible.

### T9 — Text bounding boxes (Lane A)

`EDA_TEXT::GetTextBox` ported, over T8's advances, as specified in
`geometry.md` §5.2: effective pen width
(§5.3), the `0.17` stroke fudge factor, `~{` overbar headroom, multi-line width
as the maximum and height by `interline = size.y × 1.609944`, the italic offset,
and the nine justification cases including the mirrored variants. The box is
computed unrotated and then rotated about the draw position, so the result is an
**oriented** box (centre, size, angle), not an AABB — schematic text is
routinely at 90°.

A `(face …)` font selects an outline font kicli cannot measure. Detect it and
mark the extent `approximate`, so every consumer downstream can label its
findings (`spec/SPEC.md` §8).

- **Check:** `cargo test text_boxes_match_kicad_extents` — for every text item
  in `calibration.kicad_sch`, the computed width matches the `textLength`
  measured from KiCad's SVG within 1 IU — the port should agree exactly, and the
  tolerance covers the SVG's four-decimal rounding, not a modelling gap; multi-line, bold, italic and overbar
  cases are covered; each of the nine justifications places the box on the
  documented side of the anchor; a rotated item's box is the unrotated box
  rotated about its draw position.
- **Check:** `cargo test outline_font_extents_are_marked_approximate`.

### T10 — Symbol bounding boxes (Lane A)

Two boxes, as KiCad models them (`geometry.md` §6): the **body box** (graphics
plus pins, no text) for overlap rules, and the **full box** (body ∪ visible
field boxes) for text-collision rules. Compose in library space, transform, then
union the absolute field boxes. Honour `pin_names` offset and `pin_numbers hide`
when pin text is drawn. Transform the box by its corners and normalise, which is
correct for the 90° group and only for it.

- **Check:** `cargo test symbol_body_box_excludes_field_text` — on the
  orientations fixture, the body box of each `R` is the same size at every
  orientation and swaps its axes at 90°; the full box grows when a field is
  shown and shrinks when it is hidden; a hidden field contributes nothing.

### T11 — Geometric net merges (Lane B)

Union-find over rules 1–3 of `representation.md` §3.2: coincident wire and bus
endpoints; a pin, sheet pin or junction on a segment **interior**; a pin at a
wire endpoint. Two wires crossing without a junction do **not** merge — that is
what junction dots are for. Bus entries and bus members are handled here too.
Integer geometry only.

- **Check:** `cargo test wire_geometry_alone_splits_named_nets` — on
  `sch/nets/`, rules 1–3 produce the committed pre-merge partition; the
  no-junction crossing yields two nets and the junction crossing yields one; a
  pin on a segment interior merges and a pin merely near it does not.

### T12 — Name-based net merges (Lane B)

Rules 4–5, which are what make the extractor agree with KiCad
(`representation.md` ⚠4): local labels merge within a sheet; global labels merge
project-wide; a hierarchical label merges with the parent's like-named sheet
pin; and power-symbol pins whose symbol `Value` matches merge project-wide.
Merging is sheet-path aware — the child sheet placed twice has two independent
copies of its local nets and one shared copy of its global ones.

- **Check:** `cargo test names_merge_nets_across_the_hierarchy` — on
  `sch/nets/`, the full rule set produces the committed `nets.partition`;
  removing the power-symbol rule alone increases the net count; a local label
  duplicated on the two instances of the child sheet yields two nets, and a
  global label yields one.

### T13 — Net naming and stable identifiers (Lane B)

Display-name priority: power-symbol value → user label (global > hierarchical >
local) → synthetic `#n<k>`. Synthetics are assigned by descending pin count then
by sorted pin list, so they are deterministic given the design and stable under
unrelated edits (`spec/SPEC.md` §7.1). Every net also carries **KiCad's current
net name** as an attribute, because agents need it to correlate with ERC output
and with the GUI. The synthetic id is the handle; the KiCad name never is.

- **Check:** `cargo test net_ids_survive_an_unrelated_rename` — renaming an
  unrelated symbol changes no synthetic id, while KiCad's own name for that net
  does change; the display-name priority is asserted case by case; two runs over
  one file produce identical ids.

### T14 — The netlist oracle (permanent gate, Lane B)

kicli's net partition must equal `kicad-cli sch export netlist`'s, for every
fixture (`spec/SPEC.md` §7.1, `kicad-cli.md` §4). Compare parsed content, never
bytes: the netlist embeds an absolute path and a date. Compare the **partition**
— the sets of `(refdes, pin)` — not the names, since kicli names nets its own
way by design.

The hermetic test compares against the committed `nets.netlist`. The env-gated
test regenerates it and fails if the committed oracle has gone stale.

- **Check:** `cargo test netlist_partition_matches_kicad` — the partition
  computed from `sch/nets/` equals the one parsed from committed `nets.netlist`,
  exactly, with the failure message naming the differing nets.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test netlist_oracle_is_current`.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test --features corpus
  netlist_partition_matches_kicad_corpus` — every demo hierarchy in
  `target/corpus/`, including `complex_hierarchy/ampli_ht` at its documented 25
  nets. Prints the pass count.

### T15 — Command surface, flags and exit codes (Lane C)

The `kicli <noun> <verb> [flags] [args]` skeleton of Constitution §8: global
`--output json|text` (text default), `--project <dir>`, `--sheet <path>`,
`--quiet`, `--version`. The exit-code table of `spec/SPEC.md` §6.1 is data in
one place, not scattered integers. Errors are structured JSON on **stderr** when
`--output json`. `--variant` is accepted and **hidden** in v1
(`spec/SPEC.md` §5.7).

This is where an argument parser is chosen. Recommendation: `clap` 4
(MIT OR Apache-2.0), the boring choice for a kubectl-style surface, with the
derive feature. The orchestrator rules and records the justification in the
commit message; the lane does not add the dependency itself.

- **Check:** `cargo test --test command_surface` — `--version` prints and exits
  0; an unknown verb exits 2 with usage on stderr; `--output json` renders that
  same error as one JSON object on stderr and prints nothing on stdout; every
  exit code in the table has exactly one name in the code.

### T16 — The `kicad` module: the external-binary gateway (Lane C)

One module owns discovery, the version check and the exit-code translation
(`spec/SPEC.md` §14.1, §6.2). Discovery order: `$KICLI_KICAD_CLI` →
`kicli.toml` `kicad_cli_path` → `PATH` →
`/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli`. Major version ≠ 10 is
refused with exit 6. Absence is a structured error naming the binary with an
install hint, exit 6 — never a panic and never a silent skip. **Raw pass-through
of `kicad-cli`'s codes is forbidden**; every one is translated per the §6.2
table.

The process runner sits behind a trait so tests can fake it — the one seam
`ENGINEERING.md` names for substitution. `kicli` **never** invokes
`sch upgrade` on a user file: it destroys bus aliases (`sch-format.md` §5.6).

- **Check:** `cargo test kicad_cli_codes_are_translated` — with a fake runner,
  each of `kicad-cli`'s 0/1/2/3/5/6 maps to the kicli code the §6.2 table names;
  a missing binary yields exit 6 with the install hint; a version-9 binary
  yields exit 6; no code path returns a `kicad-cli` code unchanged.
- **Check:** `cargo test no_code_path_invokes_sch_upgrade` — a source-level
  assertion over the crate, so the rule cannot be broken by accident.

### T17 — `project info` (Lane C)

The first real command. Report what the project is: project file, sheet tree
with page numbers and sheet paths, symbol and power-symbol counts per sheet, net
count, format stamps per file, prettifier mode and canonicality, bus aliases,
and whether `kicad-cli` was found and at what version. Text by default, JSON
with `--output json`, both stable and documented.

- **Check:** `cargo test --test project_commands project_info_reports_the_tree`
  — on `project/healthy/`, text output matches a committed golden and JSON
  output parses and carries the same sheet paths, counts and stamps; exit 0.

### T18 — `project check` (Lane C)

The health check, scoped to what M2 can verify. Every file parses; every file
round-trips (P1 where canonical, P2 always); every `sheet` names a file that
exists; the sheet tree has no cycle; every symbol's `instances` covers the sheet
paths it appears on and has no orphaned path; every stamp is at or below the
ceiling; comment-bearing files are named as refuse-to-write; `kicad-cli` is
present and version 10. Findings are data: exit 0 when it reports them, exit 4
only when a file cannot be read at all.

`project check` also **warms the fontconfig cache deliberately and says it is
doing so** — the first `kicad-cli` run on a machine can take over 120 seconds,
and an agent will otherwise conclude kicli has hung (`kicad-cli.md` §1.1).

Library resolution checks — `lib_id`, `Footprint` field values, `(model …)`
paths, `${KICAD9_3DMODEL_DIR}` references, nicknames with spaces — arrive with
the library module. `project check` names them as not yet covered rather than
silently passing.

- **Check:** `cargo test --test project_commands project_check_finds_each_fault`
  — on `project/broken/`, the three planted faults are reported, each with its
  file and a distinct finding kind, exit 0; on `project/healthy/`, no findings,
  exit 0; JSON output carries the same findings.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test project_check_announces_warming`
  — the warming step prints before it blocks.

### T19 — Object hashing and snapshots (Lane D)

A snapshot is `uuid → content-hash`, **hashed per object, never over file
bytes** — KiCad reorders every item on save, so a file hash makes every save
look like a total rewrite (`spec/SPEC.md` §7.3). Two hashes per object:
`h_geom` over position, orientation and size; `h_data` over everything else. The
encoding is canonical and semantic — kind, own fields in a fixed order,
coordinates as integer IU, strings as UTF-8 — and excludes file position.
SHA-256 truncated to 16 hex characters, via `sha2` (MIT OR Apache-2.0; the
orchestrator adds it).

Snapshots live in `.kicli/snapshots/<name>.snap`; `.kicli/` is gitignored.

- **Check:** `cargo test snapshot_hashes_ignore_item_order` — shuffling the
  top-level items of a fixture changes no hash; moving one symbol changes its
  `h_geom` and leaves its `h_data` untouched; editing a field value does the
  reverse; the snapshot file is byte-identical across two runs.

### T20 — The delta view (Lane D)

View 3 of `spec/SPEC.md` §7.3: added, removed, moved and edited objects, one
line each, ordered by kind then handle so the same pair of states always
produces byte-identical output. Net changes are reported as pin-set deltas, not
"net replaced". A trailing `=` count gives the unchanged denominator without
listing it.

- **Check:** `cargo test delta_distinguishes_moved_from_edited` — a fixture pair
  differing by one move, one field edit, one added symbol and one removed symbol
  produces the four documented line kinds and the correct `=` count; re-running
  the comparison is byte-identical; comparing a state with itself prints only
  the `=` line.

## Phase 3 — the views (join; needs A, B and D merged)

The orchestrator merges the lanes, runs `cargo xtask check` on the merged
result, and only then starts this phase. T21 and T22 are independent of each
other and may run as two lanes; T23 and T24 join them.

### T21 — Connectivity view (view 1)

The grammar of `spec/SPEC.md` §7.1: the `sheet` header, `S` symbol records, `N`
net records with `=<kicad-name>` when it differs, `H` child-sheet ports and `P`
own hierarchical labels. Power symbols are suppressed; `--include-power` shows
them. Ordering is stable: symbols by natural-sorted refdes, nets by descending
pin count then name, pins sorted within a net. `--uuids` appends `@<uuid8>`.

- **Check:** `cargo test connectivity_view_matches_golden` — `sch/nets/` renders
  to a committed golden byte for byte; natural sort puts `R2` before `R10`;
  `--include-power` adds exactly the suppressed symbols; `--uuids` adds a
  suffix to every record and changes nothing else.

### T22 — Layout digest (view 2)

The grammar of `spec/SPEC.md` §7.2: `page`, `L` symbol placements with `rot` and
`mirror` verbatim, `T` text and labels, `F` field offsets **only when they
differ from the library default**, `W` wire summary with crossing count, and `B`
occupancy under `--dense`. Coordinates in mm at 0.01 precision, derived from
integer IU. `--wires` enumerates instead of summarising.

- **Check:** `cargo test layout_view_matches_golden` — `sch/nets/` and
  `geometry/orientations.kicad_sch` render to committed goldens; a field left at
  its library default emits no `F` record and moving it emits one; the crossing
  count matches the fixture's planted crossings; `rot` and `mirror` come back in
  the form `sym rotate` will accept.

### T23 — View scope, budgets and `sch view`

Wire the three views to the command. Scope per `spec/SPEC.md` §7: whole project
when it fits `view.max_bytes` (default 32 KB), otherwise an index plus per-sheet
summaries, **and the output always states which mode was used**. `--sheet`
restricts to one sheet and marks the nets that leave through sheet pins.
`--stats` reports **bytes only** — no tokenizer dependency.

This carries the byte-budget ceilings of `spec/SPEC.md` §7.4, which are a named
permanent gate (§18). See R2 for the hermetic/corpus split.

- **Check:** `cargo test view_scope_switches_on_budget` — a project under the
  budget emits whole-project output and says so; the same project with
  `max_bytes` lowered emits index-plus-summaries and says so; `--sheet` marks
  the crossing nets.
- **Check:** `cargo test views_stay_within_byte_ceilings` — the in-repo
  fixtures stay inside their committed ceilings, and the compression ratio
  against the source file is asserted, so a regression that doubles the output
  fails even on a small fixture.
- **Check:** `cargo test --features corpus views_stay_within_byte_ceilings_corpus`
  — connectivity ≤ 2 KB on a median sheet, ≤ 9 KB at 234 symbols; layout
  ≤ 10 KB at 234 symbols; both together ≤ 18 KB. The test prints the measured
  bytes per sheet, so a near-miss is visible before it becomes a failure.

### T24 — The JSON twin

Every view has a JSON form carrying identical content, opt-in via
`--output json` (Constitution §6). The measured cost is 2.3× minified, which is
why it is not the default. Field names are stable and documented; `kicad_name`
is the net attribute of §7.1.

- **Check:** `cargo test json_view_carries_the_same_content` — for each of the
  three views, the JSON parses, and a projection of it back to the terse form
  reproduces the text output byte for byte; the measured size ratio is printed
  and asserted below 3×.

### T25 — `AGENT.md` first edition and the API M3 consumes

Constitution §10: a feature undocumented for agents is unfinished, and §8 makes
docs part of the same change as the command surface. Ship the first `AGENT.md`:
the commands that exist (`project info`, `project check`, `sch view`), the
representation format guide for all three views, the **full exit-code table
including the `kicad-cli` translation**, and the statement that `sch view` is
the truth an agent acts on.

Freeze what M3 consumes: the item model and handles, `SheetPath`, the transform
and pin resolver, both bounding boxes, text extents, the net partition and its
handles, and the snapshot/delta API. Every public item has rustdoc with a
doctest, as M1 T25 established.

- **Check:** `cargo doc --no-deps` clean with `#![deny(missing_docs)]`, and
  `cargo test --doc`.
- **Check:** `cargo test agent_doc_covers_every_command` — every command and
  global flag the binary accepts appears in `AGENT.md`, and every exit code in
  the table appears with its meaning. The test reads both the code and the
  document, so the two cannot drift.

## Milestone exit criteria

M2 is complete when all of the following pass on a clean checkout:

```sh
cargo xtask check                            # fmt, clippy, test, doc, deny
cargo test                                   # hermetic: fixtures only
cargo xtask corpus
cargo test --features corpus
KICLI_TEST_KICAD_CLI=1 cargo test --features corpus
```

with these named gates green:

| Gate | Assertion |
|---|---|
| pin fixture | 16/16 orientations exact, plus the asymmetric symbol |
| ERC JSON canary | `json.pos × 100 == text.pos`, expecting the bug |
| netlist oracle | kicli's partition equals `kicad-cli`'s on every fixture and every demo hierarchy |
| view budgets | connectivity ≤ 2 KB median and ≤ 9 KB at 234 symbols; layout ≤ 10 KB; both ≤ 18 KB |
| determinism | two runs of every view, snapshot and delta are byte-identical |
| round trip | M1's P1 and P2 still hold on every fixture, including the new ones |

M2 ships read-only. No command in this milestone writes a `.kicad_sch`.
