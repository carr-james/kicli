# M4 — Wiring

Cut from `spec/SPEC.md` §6, §9, §15, §18, §19 plus `research/wire-routing.md`
(R9) and `research/style-rules.md` §4. Code standards and the gate list come
from `ENGINEERING.md`. The mutation write path M3 froze — the atomic write, the
invariant pass, the mutation result — is the floor every verb here builds on.

**Goal of M4.** kicli draws a wire the way a person would, and says what the
wire cost. `wire connect` runs a deterministic orthogonal router and reports the
route with its cost breakdown, so an agent can accept the route or move a symbol
instead. `wire draw` takes explicit vertices and refuses an illegal one. Every
route the router writes reads in KiCad as the connection kicli claimed.

**Rules for this milestone.**

- Constitution §11: every task below names an executable completion check. A
  task is not done until that exact command passes.
- `ENGINEERING.md`: **`cargo xtask check` must pass at every commit.**
- `CLAUDE.md`: the orchestrator runs the full check, corpus included, at every
  lane merge. Corpus and environment gates do not run in a lane worktree.
- `ENGINEERING.md` "Testing pyramid": write the test before the implementation.
  Fixture expectations are verified against KiCad, never hand-asserted.
- Constitution §4: the router holds **no floating point**. Every cost is `i64`,
  every coordinate is `Iu`. The rule has an executable twin in T8.
- Every wire write goes through M3's path: a `kicli-sexpr` tree edit, the
  invariant pass, the atomic write, one delta fragment. No new way to write
  bytes appears in this milestone.
- **The weights are not retuned in this milestone.** `w_turn`, `w_cross`,
  `w_text`, `w_near` and `label_threshold` are shared with M5's rules, so
  changing one changes what the linter scores. If the calibration gate (T20)
  falls outside 15 %, the task reports the measured deviation and parks it for
  James. It does not move a weight until the gate passes.
- No scoring, no rendering, no bus routing, no rip-up-and-reroute.

## Resolved — one term, one vocabulary

**Ruled by James, from the ergonomics pass.** The label kinds were written two
ways: `label add --kind` took `local|global|hierarchical`, and the layout view's
`T` line printed `label|global|hier`. An agent read `T hier PORT_A …` and had to
know to write `--kind hierarchical`.

**The view adopts the flag's words.** The view is what an agent copies from, so
its vocabulary is the load-bearing one. The eight bytes a hierarchical-label
line grows are noise against the §7.4 budget, and an alias on the flag would
leave two right answers, which is the thing one-term-per-concept exists to
prevent. `view_layout.golden` was refreshed in the same commit — the golden
change is the change — and `AGENT.md`'s mapping paragraph shrank to the single
canonical list.

**Proposed while implementing, affirmed on review: the snapshot keeps KiCad's
record names.** The file under `.kicli/` writes `label`, `global_label` and
`hierarchical_label`, beside `no_connect`, `bus_entry` and `sheet_pin`. Three
legs hold it up: these are KiCad's record names rather than a third synonym; the
file must round-trip a kind this version has never seen, which `Other(token)`
does by keeping the file's own word; and it is machine-keyed rather than read by
hand. The vocabulary rule governs the **agent-facing surface** — views, verbs,
documentation — and a snapshot is a wire format, which keeps its source-of-truth
names. Half-translating three of fifteen tokens would stale every snapshot
already written and leave the set in two vocabularies at once.
`ObjectKind::token`'s documentation states this where the tokens are defined, so
it is not re-argued.

Nothing about this is open.

## Phase 0 — the probe harness (sequential, orchestrator, no parallel lanes)

### T1 — The probe crate, and the drawing builder ✅

A new workspace member, `crates/kicli-probe`, holds the drawing builder that
`net_probe_rules.rs` grew: the `Probe` item-by-item writer, `Placed`, the
library-symbol builders (`symbol`, `pin`, `hidden_pin`, `power`, `resistor`),
the sheet builders that take a port angle, the strand and bundle shorthands,
`millimetres`, and `check_precision`.

Two properties of the builder are the reason it is worth a crate. A port whose
angle disagrees with its position is moved by KiCad, which takes it off the wire
the probe drew — so the sheet builders take the angle and justify from it. And a
coordinate with more than four decimals is not a coordinate KiCad writes, so
`write` refuses the drawing before any tool sees it. Both were paid for by a
probe that measured its own defect and called it a finding.

**Dependency direction.** `kicli-probe` depends on `kicli` and `kicli-sexpr`;
`kicli` dev-depends on `kicli-probe`. The cycle is dev-only, which cargo
resolves, and it is what lets the builder own `partition_with` — the helper all
16 probes call. `ENGINEERING.md`'s structure section gains the crate and the
statement that the edge is dev-only, in the same commit. The licence allowlist
does not govern a dev-dependency; advisories still do (`ENGINEERING.md`,
Dependencies).

The crate carries the same lints as the others: `deny(missing_docs)`,
`deny(unsafe_code)`, `warn(clippy::pedantic)`.

- **Check:** `cargo test -p kicli-probe` — the builder's own unit tests:
  `a_number_kicad_would_not_write_is_refused` plants a coordinate with five
  decimals and the writer refuses it; `two_runs_write_one_drawing` writes the
  same probe twice and the bytes are equal, because the identifiers come from a
  counter and not a random source.
- **Check:** `cargo test --test net_probe_rules` — the 16 probes pass with the
  builder deleted from the test file.
- **Check:** `cargo test --test probe_crate_is_dev_only` — a workspace-reading

**Fallback, if the dev-only cycle fights the tooling:** keep `kicli-probe` on

- **Check:** `cargo test config_reads_every_routing_key` — each key parses to

  and a misspelled key is still an error.
- **Check:** `cargo test --test the_label_threshold_has_one_name` — a

**Added beyond the brief, and accepted on review: a negative weight or distance
is refused where it is read.** A negative weight does not merely produce an odd
route — it breaks A*'s admissibility, because the heuristic's guarantee rests on
every cost term being non-negative, so the search stops finding the cheapest
path at all. Config-read is the cheapest catch point: the alternative is finding
it in a route nobody can explain.
`a_cost_that_would_break_the_search_is_refused` holds both, with zero accepted
as the control. `spec/SPEC.md` §15 states the rule beside the keys.

**`AGENT.md` does not list `[routing]` yet**, because no command reads it. It
gains the section in T16, with the verbs that read it. What `AGENT.md` says now
is the thing that is true today: every known section is validated, so a typo is
an error the moment it is written.

### T6 — Terminals, and the escape rule ✅

A terminal is a symbol pin, a sheet pin, or a point on an existing net. Resolve
one the way the M3 verbs resolve an object: by reference designator on the sheet
path being edited, or by identifier.

A route must step at least 1 G along the pin's own direction before it turns,
at both ends. A wire that approaches a pin from the side reads wrong and
overlaps the marker on a clock or inverted pin. This is a hard constraint and
not a cost: a terminal whose escape point is blocked is `blocked`, with the
blocking object named.

- **Check:** `cargo test a_route_leaves_a_pin_along_its_own_direction` — a probe
  symbol carries one pin on each of its four edges, placed upright and mirrored
  both ways; in every case the escape point is one grid step **outside the
  symbol's body box**, and the step the other way lands on the body.

**Corrected while implementing.** This check first said the first vertex is
"1 G along the pin direction". A pin's stored angle points from its connection
point **towards the body**, so a route leaves along the reverse of it. KiCad's
own `Device:R` settles the direction rather than memory: pin 1 at `(0, 3.81)`,
angle 270, length 1.27, and a body rectangle whose top edge is at 2.54 — so the
root lands exactly on the body and the angle points inwards. `SCH_PIN::GetPinRoot`
in `eeschema/sch_pin.cpp` gives the same rule for every orientation, with the
file angle mapped at `sch_io_kicad_sexpr_parser.cpp:1673`.

The test states the rule against the **body box** rather than against the sign
in the code, so an inverted sign fails it. That was checked by inverting the
sign and watching it fail, which is the control this check needed.

**Two additions to the harness, built here and needed by T7:** a `Placed` may
carry an angle and a mirror, and `rectangle()` gives a probe symbol a body. A
symbol that occupies no space cannot obstruct a route, so the obstacle map has
no probe to measure without them.

**A sheet pin's angle means something else, and the difference is a trap.** It
names the **edge the pin sits on**, counting anticlockwise from the right with
y upwards: 0 right, 90 top, 180 left, 270 bottom
(`sch_io_kicad_sexpr_parser.cpp`, `parseSchSheetPin`). A wire leaves outwards
from that edge, so the heading is the angle reflected into the schematic's
y-down sense — 90 means *up the page*. `a_sheet_pin_leaves_the_edge_it_sits_on`
pins the mapping. It is established from KiCad's source and **not yet measured
against the running tool**; the first task that routes to a sheet pin owes it a
probe.
- **Check:** `cargo test a_blocked_escape_is_reported_and_not_routed_around` —
  a pin boxed in by another symbol's body yields `blocked` naming that symbol,
  and writes nothing.

### T7 — The routing window and the obstacle map

The window is the bounding box of the two terminals, inflated by
`routing.margin`, clipped to the page. Obstacles are looked up in a hash grid
keyed by grid cell, built once per request.

`research/wire-routing.md` §3.2's table becomes a closed enum with an exhaustive
match, so a new schematic object type is a compile error at the one site that
must decide about it. The two rows that carry the whole design: a **collinear or
overlapping wire of another net is a hard block**, because a wire drawn along
another net's wire renders as a connection; a **perpendicular crossing is
allowed and costed**.

**A foreign wire's treatment depends on the route's heading, so the map cannot
be a set of blocked points.** Collinear and crossing are not two kinds of wire;
they are one wire met two ways. A cell holding a horizontal wire blocks a route
travelling horizontally through it and costs `w_cross` for one travelling
vertically. The query is therefore `entering(point, heading)` rather than
`blocked(point)`, and a cell stores the **axis** of any wire on it. Every other
row of the table is heading-independent and answers the same either way.

- **Check:** `cargo test every_obstacle_kind_is_classified` — one case per row
  of the table, each on a probe drawing that contains only that object. The
  match that classifies them is exhaustive over a closed enum, so a new
  schematic object type is a compile error at the one site that must decide
  about it.
- **Check:** `cargo test a_collinear_wire_blocks_and_a_crossing_does_not` — the
  **same cell** of the **same map**, queried with two headings, answers two
  verdicts: blocked along the wire's own axis, costed across it. Querying two
  drawings would test two maps and leave the heading dependence itself
  unmeasured, which is the one thing this check exists for.
- **Check:** `cargo test the_window_is_clipped_to_the_page` — a terminal near
  the page edge yields no lattice node outside the border.

**Partly built, and not ticked. What is done:** `route::window` — the window
around two terminals, inflated by the margin, clipped to the page, with the
lattice addressed by integer cell so no search compares coordinates twice. And
`route::obstacles` — §3.2's table as a closed enum, `Feature::treatment`
exhaustive over it, `Obstacles::build` sorting a sheet's geometry onto the
lattice in one pass, and `Obstacles::entering(point, heading)` answering a
`Verdict` that carries what blocked the step or what it costs. Both compile
clean and the six gates pass.

**What is left, and it is the half that measures rather than the half that
computes:**

1. **The adapter from a sheet to `SheetGeometry`.** The search is pure over
   lists of boxes, pins and segments, because deciding which wires belong to
   the net being routed is connectivity's work rather than the search's. Nothing
   yet turns a loaded `Schematic` into those lists — symbol bodies through
   `symbol_boxes`, pins through `resolve_pins`, label and text boxes through
   `text_box`, and wires split into own-net and foreign by the extractor. It is
   production code that T17 and T18 need as much as this task does.
2. **The three checks, on probe drawings.** They are deliberately not written
   against a hand-built `SheetGeometry`: a hand-made rectangle encodes the same
   assumption as the code that reads one, and would agree with a body box that
   is in the wrong place. The probe harness now writes symbols with bodies,
   at an angle and mirrored, so the drawings these checks need can be built.

**Two cases are required rather than optional**, both because they cover
decisions that would otherwise pass silently against convenient fixtures:

1. **The heading dependence, on one cell.** One map, one cell holding one
   foreign wire, two queries, two verdicts. The check above carries it.
2. **The window-relative lattice.** `points_in` aligns to the window's own
   origin rather than to absolute zero, so a body box whose corner is off the
   grid still marks the grid points it covers. A fixture whose boxes happen to
   start on grid agrees with either behaviour and measures neither.

### T8 — The cost model, in integers

```
cost = w_len·steps + w_turn·corners + w_cross·crossings
     + w_text·steps_in_text + w_near·steps_within_1G_of_a_body
```

The breakdown is the point of the exercise, so it is computed as parts and
summed, never as a total with parts reconstructed for display. An agent reads
the parts to decide whether to move a symbol instead.

- **Check:** `cargo test the_cost_breakdown_sums_to_its_total` — over generated
  paths, the five terms sum to the reported total.
- **Check:** `cargo test the_weights_keep_their_documented_order` — one crossing
  costs more than a twenty-step detour and less than two; one corner costs more
  than a five-step detour. These are the rationale sentences in
  `research/wire-routing.md` §6, made executable.
- **Check:** `cargo test --test the_router_holds_no_floating_point` — a
  workspace-reading test: no `f32` or `f64` appears under `src/route/`.
  Constitution §4 says determinism is the whole game; clippy has no lint for it.

### T9 — Candidate shapes, in the fixed order (Lane A)

I, L(h-first), L(v-first), Z(vertical-mid, `m` ascending), Z(horizontal-mid,
`m` ascending), U(offset ascending). Each candidate is validated against the
obstacle map and costed; the cheapest wins; ties break by fewer corners, then
shorter length, then the lexicographically smallest vertex sequence.

Shapes come first because A* with a corner penalty finds *a* minimal route and
often not the one a person would draw, and because half of all real segments are
under 7 mm — the fast path is the common path, not an optimisation.

- **Check:** `cargo test each_shape_is_drawn_when_it_is_the_cheapest` — one
  probe drawing per shape, and the route is that shape.
- **Check:** `cargo test equal_cost_shapes_break_the_documented_way` — a drawing
  where two shapes cost the same yields the earlier one in the enumeration, and
  the report's `alternatives_considered` counts every candidate tried.

### T10 — A* over turn-aware states (Lane A)

States are `(x, y, dir)`; expansion order is fixed at `+x, −x, +y, −y`; the
queue orders on the total order `(f, g, x, y, dir)`, so no tie is ever resolved
by heap internals. The heuristic is Manhattan distance times `w_len`, plus
`w_turn` when a turn is unavoidable, which is admissible because every term is
non-negative.

A failure is never a bare failure. `blocked` carries the handles of the objects
that blocked it, because an agent given a list can act.

- **Check:** `cargo test a_star_routes_what_no_shape_can` — a drawing whose
  obstacles defeat every shape, and the path found is orthogonal, on grid, and
  free of hard blocks.
- **Check:** `cargo test a_blocked_route_names_what_blocked_it` — the handles
  are real identifiers of real objects, and nothing is written.
- **Check:** `cargo test the_queue_order_is_total` — over generated state pairs,
  the comparator is antisymmetric and never reports two distinct states equal.

### T11 — Determinism, as a property test (Lane A)

For every fixture and every pair of terminals: routing 100 times, and across a
shuffled item order — KiCad reorders items, so the file's order is not a stable
input — yields byte-identical output.

`proptest` becomes a dev-dependency of `kicli`; it is already one of
`kicli-sexpr`, and the justification goes in the commit message per
`ENGINEERING.md`.

- **Check:** `cargo test --test route_determinism` —
  `routing_is_identical_across_a_hundred_runs` and
  `routing_is_identical_across_a_shuffled_item_order`.
- **Check:** `cargo test --test the_router_iterates_no_hash_map` — a
  workspace-reading test over `src/route/`: no `HashMap` or `HashSet` iteration
  feeds a decision. `BTreeMap` and sorted vectors are the tools.

### T12 — Four-way avoidance, on the refusal that already exists (Lane A)

M3 T14 built the four-way junction refusal in `edit::mark`, with the wire-end
detection behind it. The router does not grow a second one. Where a route would
terminate such that four wire ends meet, it offsets by 1 G and **reports that it
did**, so the drawing never needs the linter's `KI-JCT-001` to notice.

- **Check:** `cargo test the_router_never_makes_a_four_way_junction` — a drawing
  whose natural terminus is a three-end point: the route lands 1 G away, the
  report names the adjustment, and `mark::add_junction` at the terminus is still
  refused afterwards, which proves the offset avoided the shape rather than
  hiding it.
- **Check:** `cargo test --test the_four_way_rule_has_one_home` — a
  workspace-reading test: one implementation of the four-end detection, called
  by both the mark verb and the router.

### T13 — The label proposal, at the shared threshold (Lane A)

When the best path exceeds `routing.label_threshold`, or A* reports blocked, the
router proposes paired labels. It **proposes**; `--auto-labels` performs it and
the output says so. The name comes from the net's existing name, or
`<source-ref>_<pin-name>` when the net is unnamed.

- **Check:** `cargo test a_long_route_is_proposed_as_labels_and_not_drawn` —
  status `labels`, the reason names both the length and the threshold, and the
  file is byte-identical afterwards.
- **Check:** `cargo test auto_labels_writes_the_pair_and_says_so` — two labels
  land 2 G along each pin's direction, on grid, and the extractor joins the two
  pins.
- **Check:** `cargo test the_threshold_is_the_configured_one` — a `kicli.toml`
  that lowers `routing.label_threshold` moves the boundary, on the same drawing.

### T14 — `wire draw`: explicit vertices, validated (Lane B)

Vertices given, no search. kicli validates — orthogonal, on grid, no hard-block
violation, escape honoured at both ends — and refuses with a structured error
rather than drawing something illegal. A valid polyline writes one two-point
`(wire (pts …))` record per segment, because KiCad wires are always two-point.

**This task owes a probe, carried from T6.** `wire draw` validates that the
escape is honoured at both ends, so it is the first task to use a **sheet pin's**
escape direction in anger. That direction is established from KiCad's parser and
has never been measured against the running tool: a sheet pin's angle names the
edge it sits on rather than the direction of its graphic, which is the reverse
of what the same number means on a symbol pin. Measure it here — draw a port on
each of the four edges, run a wire outwards from each, and let `kicad-cli` say
which ones connect — and record the result beside the rule in
`route::terminal`. A read-from-source rule and a measured-against-the-tool rule
are not the same claim, and this one must not stay the first kind by default.

- **Check:** `cargo test explicit_vertices_are_validated_before_anything_is_written`
  — a diagonal, an off-grid vertex and a segment through a symbol body are each
  refused, each names the offending vertex, and each writes nothing.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test a_sheet_pin_leaves_the_edge_kicad_puts_it_on`
  — the four edges, measured against the tool rather than read from its source.
- **Check:** `cargo test a_drawn_polyline_is_one_record_per_segment` — the
  record count matches the segment count, the invariants pass, and the extractor
  reports the connection the caller asked for.
- **Check:** `cargo test a_wire_command_changes_only_its_own_lines` — P3, per
  command, on M1's `changed_line_count`.

### T15 — `wire delete` (Lane B)

Delete a segment by identifier. The command removes what it was asked for and
nothing else: it does not cascade into junctions, because a junction that now
sits on two ends is legal and removing it is a second decision. It **reports**
every junction that now joins fewer than three ends, so the caller can act.

- **Check:** `cargo test deleting_a_wire_splits_what_it_joined` — the extractor
  reports two nets where it reported one, and the invariants pass.
- **Check:** `cargo test a_deleted_wire_reports_the_junctions_it_stranded` — the
  report names them, and they are still in the file.

### T16 — The verb surface and the output contract (Lane B)

`kicli wire connect|draw|delete` in `cli`, with `--output json` carrying the
mutation result. The router's report is the shape in
`research/wire-routing.md` §8: path, segments, corners, length, the five-part
cost breakdown, the crossings with their nets, the handles added, and
`alternatives_considered`.

`status` ∈ `routed | labels | blocked | invalid`. The exit codes follow M3's
refusal convention and are recorded here so they are not re-argued: `routed` and
`labels` exit 0 — a proposal is a result, not a failure — and `blocked` and
`invalid` exit 1, a well-formed request that could not be completed.

- **Check:** `cargo test --test command_surface` — every wire verb parses, and
  every refusal exits the code its row names.
- **Check:** `cargo test --test wire_output_contract` — one golden per status,
  text and JSON, with the JSON keys exactly §8's.

### T17 — `sch view --view delta`, the command M3 left unwired (Lane B)

The machinery exists and the semantics are ruled; only the verb is missing.
`view::delta` compares two snapshots, `view::snapshot` takes, writes and reads
one, and every mutation already updates `@last-write`.

The delta answers **"what has touched this file since kicli last wrote it?"** It
is empty immediately after a mutation, by design, because that mutation's own
result already reported what it changed. The command's help says so, in those
words, because the spec itself expected the other reading.

Two things the command must state rather than let a caller assume. A comparison
against a **file** degrades to hashes and names, because a snapshot file does
not hold the old values an in-memory comparison prints — so the output says
which form it is. And a project kicli has never written has no snapshot: that is
a structured error naming `@last-write`, not an empty delta.

`--against <name>` compares against a named snapshot; the default is
`@last-write`. The output obeys the §7.4 budget model like the other two views.

- **Check:** `cargo test --test delta_view` — a mutation followed by a delta
  reports nothing changed; an edit written to the file behind kicli's back, the
  way an editor makes one, reports exactly that object; the JSON twin carries
  the same content as the text form.
- **Check:** `cargo test --test command_surface` — `--view delta` parses, and a
  project with no snapshot exits the code its table row names.
- **Check:** `cargo test agent_doc_covers_every_command` — `AGENT.md` documents
  the verb and the distinction it draws with the mutation result.

### T19 — `wire connect <pin> <net>`

The common agent request — "connect `U1.7` to `+3V3`" — and first-class, not a

- **Check:** `cargo test connecting_to_a_net_takes_the_nearest_terminal` — a net

  joined.
- **Check:** `cargo test a_net_is_addressed_by_name_or_by_handle` — both forms
  resolve, and an ambiguous name is refused with the candidates listed.

### T20 — The re-route calibration gate, at 15 %

The objective measure of whether the weights are right. Re-route every net of a
known-good sheet from scratch and assert the total cost is within 15 % of the
original.

The procedure is stated here because the gate is meaningless without it:

1. Take each net with two or more pins on one sheet and no bus involvement.
2. Cost the net's **existing** wires with the same cost function, against the
   sheet with that net's own wires removed — so the original and the re-route
   see the same obstacles.
3. Re-route: build a spanning tree over the net's pins by Manhattan distance,
   ties broken by `(x, y)`; route each tree edge in order; add each result to
   the obstacle map before the next edge.
4. Sum both over the sheet. Assert the deviation is within 15 % **in either
   direction**. A result far under the human's cost is evidence of divergence
   and not a win: the likely cause is a cost function that fails to price
   something the person was avoiding, such as a crossing or a label the route
   runs through. Cheap is an anomaly to explain, never a number to bank.
5. Report the per-net deviation, and **name every net skipped and why**. Assert
   the skipped pins are under a quarter of the sheet's pins, so the gate cannot
   pass by skipping the hard nets.

Two sheets. A purpose-built in-repo fixture gates the default run — tidy, at
least 20 nets and 40 segments, a mix of I, L and Z shapes, canonicalised with
`kicad-cli sch upgrade --force`. The tidy hand-drawn demo sheet `ampli_ht`
measured in `research/wire-routing.md` §2 gates the corpus run.

If either sheet falls outside 15 %, the task reports the deviation and parks it.
It does not move a weight: the weights are M5's too.

- **Check:** `cargo test re_routing_a_known_good_sheet_costs_what_the_original_did`.
- **Check:** `cargo test --features corpus re_routing_a_demo_sheet_costs_what_the_original_did`.

### T21 — The whole loop, end to end, against KiCad

One test that does what an agent does with wires: read a view, connect two pins,

- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test --test wire_loop` — the netlist

## Milestone exit criteria

M4 is complete when all of the following pass on a clean checkout:

```sh
cargo xtask check
cargo test
cargo xtask corpus
cargo test --features corpus
KICLI_TEST_KICAD_CLI=1 cargo test --features corpus
```

with these gates green:

| Gate | Assertion |
|---|---|
| probe harness | one home for the builder, the oracle and the scratch copy; no test file carries a copy; the crate is a dev-dependency only |
| determinism | 100 runs and a shuffled item order yield byte-identical output |
| no floating point | none under `src/route/`, and no hash-map iteration feeds a decision |
| escape | every route leaves and enters along the pin's own direction |
| collinear block | a wire is never drawn along another net's wire |
| four-way | the router never creates one; it offsets by 1 G and reports it |
| one knob | `routing.label_threshold` is the only threshold, read by the router and by `KI-LBL-001` when M5 arrives |
| refusals | a diagonal, an off-grid vertex, a blocked escape: each exits its documented code and writes nothing |
| calibration | the in-repo sheet and `ampli_ht` re-route within 15 %, with the skipped nets named |
| netlist oracle | still 35 of 35 demo hierarchies |
| round trip | P1 and P2 hold on every fixture after every wire write |
| locality | a wire command changes only its own object's lines |
| KiCad agrees | the netlist of every written file carries the partition the route reported |

M4 ships the first commands that route. Nothing in it scores a drawing.
