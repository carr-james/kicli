# M3 — Mutations

Cut from `spec/SPEC.md` §5.4, §5.6, §6, §7.3, §8, §10, §19 plus
`research/geometry.md` (R7) §4 and `research/sch-format.md` (R1) §3. Code
standards and the gate list come from `ENGINEERING.md`. The API M2 froze is the
floor everything here builds on.

**Goal of M3.** kicli changes a schematic and proves it did no harm. Every
mutating command writes atomically, re-runs the cheap invariants, reports what
it touched as a delta fragment, and touches nothing else in the file.
Constitution §2 — anything a human can move, kicli can move — becomes true for
symbols, fields, text, labels, junctions and no-connects.

**Rules for this milestone.**

- Constitution §11: every task below names an executable completion check. A
  task is not done until that exact command passes.
- `ENGINEERING.md`: **`cargo xtask check` must pass at every commit**.
- **`CLAUDE.md`, amended after M2: the orchestrator runs the full check, corpus
  included, at every lane merge.** The corpus and environment gates do not run
  in a lane worktree, and M2 shipped two green lanes whose gates failed the
  moment they reached main.
- `ENGINEERING.md` "Testing pyramid": write the test before the implementation.
  Fixture expectations are verified against KiCad, never hand-asserted.
- Every mutating command is a `kicli-sexpr` tree edit, an invariant run, an
  atomic write, and a delta fragment. No command writes bytes any other way.
- P1 and P2 still hold after every mutation. P3 — an edit changes only its own
  region — becomes a gate here, per command.
- No wire routing, no scoring, no rendering. `wire` arrives in M4.

## Resolved — decisions carried in from M2, recorded so they are not re-opened

**The netlist oracle is a rolling defect lane, and it gates M4.**
22 of 35 demo hierarchies match KiCad exactly. The rest differ by a few nets
each. James's target: **full 35/35 parity before M4 starts**, because the router
and `KI-CONN-001` both stand on the extractor. The lane runs through M3
alongside the mutation work, and each fix names the demo hierarchy that exposed
it in its commit message. Tasks T18–T20.

**A snapshot file keys on the whole identifier, not eight characters.** M2's
delta lane found that eight hex characters do not identify: every object of one
fixture shares them. The delta prints `uuid8` as a handle and the file keys on
the whole thing. M3's mutation echo uses the same encoding.

**SPEC §7.3's snapshot line cannot produce SPEC §7.3's own example delta**,
which needs old values the four-column file does not hold. M2 left both
statements standing: an in-memory comparison keeps the rich form, a file-based
one degrades to hashes and names. **M3 is where this bites** — `@last-write` is
written by mutations and read by the next command — so T5 decides it.

**Pre-approved by James:** amend §7.3 to the minimal extension that reproduces
its own worked example, a fifth display column if that is what it takes, in the
same commit as the implementation. Three requirements bound the choice: the
format stays stable and documented, object identity stays keyed on the UUID, and
the delta view still fits the §7.4 budget model. A minimal fix that breaks one
of those comes back to James instead.

**Extending `kicli-sexpr` is in-kind, and M3 ends with a new freeze.** M1's
freeze was a stability guarantee for M2's consumers, not a vow of immutability.
T1 adds `insert_child` and `remove`; the existing API is untouched, the
round-trip properties gate the extension, and the enlarged surface is frozen
again at the end of this milestone.

**The oracle pattern is now standing policy.** Nine checks in this milestone
verify the file kicli actually wrote against KiCad's own reading of it, rather
than against kicli's arithmetic. James: keep that pattern for every mutation
lane in every future milestone.

Nothing in M3 is blocked.

## Phase 0 — the write path (sequential, orchestrator, no parallel lanes)

Every command in this milestone is built on these five. They land in order and
nothing runs beside them.

### T1 — Tree editing in `kicli-sexpr` ✅

M1 froze `Doc::set_atom`, which changes a value in place. A mutation also adds
and removes objects, and the parser crate has no way to do either. Add
`insert_child`, `remove`, and `replace_children`, with `NodeId` stability rules
stated: an identifier stays valid until the node it names is removed.

The two round-trip properties must survive an edit. An untouched subtree still
emits from its original span, so a file with one symbol added is byte-identical
everywhere else.

- **Check:** `cargo test -p kicli-sexpr edits_keep_the_round_trip_properties` —
  for every fixture: insert a subtree, remove it again, and the document emits
  its original bytes; insert a subtree and re-parse, and the tree matches what
  was built; `structurally_eq` holds across an emit and re-parse of an edited
  document.
- **Check:** `cargo test -p kicli-sexpr an_edit_touches_only_its_own_lines` —
  `changed_line_count` for a one-atom edit stays ≤ 3, and for an inserted item
  equals the lines that item occupies.

### T2 — The atomic write ✅

`write temp → verify → rename`, in one place that every command calls. The
verify step re-parses the bytes actually written, not the tree in memory.
Failure means exit 3 and **no file changed**: the temporary file goes away and
the original is untouched.

Honour `plan_write`'s refusals, which M1 built: a stamp above the ceiling and a
file carrying `#` comments are refused before anything is written, exit 4. A
non-canonical file is reformatted and the result says so.

The temporary file lives beside the target, so the rename is on one filesystem
and is therefore atomic.

- **Check:** `cargo test atomic_write_leaves_the_original_alone` — a write whose
  verify step fails leaves the file byte-identical and no temporary behind; a
  refusal writes nothing; a successful write renames into place and the result
  reports whether it reformatted.
- **Check:** `cargo test a_write_verifies_the_bytes_and_not_the_tree` — a
  document whose emit is corrupted by a fault injected in the emitter is caught
  by the verify step rather than by the next read.

### T3 — The auto-invariant set ✅

Constitution §5's four checks, as one named, reusable pass that every mutation
runs and every mutation reports: the output re-parses; every UUID a file
references still exists; connectable geometry is on grid; no instance data is
orphaned.

Each invariant is a separate finding with its own name, so a report says which
one failed rather than that something did. The pass is pure over the model, so
it is cheap enough to run on every mutation, which is the point.

- **Check:** `cargo test invariants_catch_what_they_are_named_for` — four
  planted faults, one per invariant: a truncated emit, a symbol instance whose
  sheet path no longer resolves, a pin moved off grid, and an `instances` entry
  for a sheet that is gone. Each is caught by its own invariant and named.
- **Check:** `cargo test invariants_pass_on_every_fixture` — the whole fixture
  tree is clean before any mutation, so a failure later is the mutation's fault.

### T4 — The mutation result ✅

What a mutating command returns, in text and JSON: the objects it changed as a
delta fragment, the invariant results, whether the file was reformatted, and the
handles a caller needs to address what was just made.

Constitution §5 says every mutation is verified and reported. The delta
vocabulary of `view::delta` is the report, so a caller reads one form for "what
changed" whether it asked for a delta or made one.

- **Check:** `cargo test a_mutation_reports_what_it_touched` — a field edit
  reports one changed object, four passing invariants and `reformatted: false`;
  the JSON form carries the same content; the text form is one line per changed
  object.

### T5 — `@last-write`, and what a snapshot file can say ✅

Every mutation updates the implicit `@last-write` snapshot under `.kicli/`, so
the next command can answer "what did my last command change?" without
bookkeeping.

This is where M2's open question about the snapshot format has to be settled:
the four-column file cannot reproduce the worked example in `spec/SPEC.md` §7.3.
Decide it, implement it, and amend §7.3 in the same commit if the answer changes
the file.

- **Check:** `cargo test the_last_write_snapshot_follows_every_mutation` — two
  mutations in a row, and a delta against `@last-write` after each reports
  exactly the second one's objects.
- **Check:** `cargo test a_delta_against_a_saved_state_reads_like_one_against_a_design`
  — a comparison against a saved state and one against the design it came from
  produce the same bytes.

### T6 — `sym move`, `sym rotate`, `sym mirror` (Lane A) ✅

Move by a delta or to a position; rotate to an absolute angle; mirror about an
axis. All three snap to the grid by exact integer arithmetic,
round-half-away-from-zero, unless `--off-grid` says otherwise — and `--off-grid`
is itself a finding, so a caller feels it.

**Fields move rigidly with the symbol** and keep their own angles; a rotation
carries their positions about the anchor. `--keep-field-positions` opts out.
Every command that sets a field position clears `fields_autoplaced`, or KiCad
overwrites the work on next open.

- **Check:** `cargo test a_moved_symbol_takes_its_fields_with_it` — the offsets
  from anchor to each field are unchanged after a move, and after a rotation
  each field's offset is the rotated one while its own angle is not.
- **Check:** `cargo test a_placement_lands_on_the_grid` — a move to an off-grid
  position snaps, the report says it snapped, and `--off-grid` places it exactly
  and reports a finding.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test a_rotated_symbol_is_where_kicad_draws_it`
  — after a rotation, the pin positions kicli computes match KiCad's own rule
  check on the written file. The oracle decides, not the arithmetic.

### T7 — `sym place` and `sym delete` (Lane A) ✅

Place a symbol from a library, and delete one. Placing **must copy the
definition into the sheet's `lib_symbols`**: KiCad draws the embedded copy, and
a placement whose definition is missing draws as a placeholder. Deleting must
leave no orphan — the instance data goes with the symbol, and the embedded
definition stays if another placement still uses it.

A new symbol needs a new UUID and instance data for every sheet path the sheet
is placed on. A sheet placed twice gets two references, which is where most
tools get this wrong.

- **Check:** `cargo test a_placed_symbol_carries_its_definition` — the file's
  `lib_symbols` gains the definition, the placement resolves through it, and the
  written file's pins are where the geometry says.
- **Check:** `cargo test a_placement_on_a_twice_placed_sheet_gets_two_references`.
- **Check:** `cargo test a_deleted_symbol_leaves_no_trace` — the instance data
  goes, the invariants pass, and a definition still used by another placement
  stays.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test kicad_reads_what_place_wrote` —
  the rule check on the written file reports the new symbol's pins and no new
  fault of its own.

### T8 — Locality, for every symbol command (Lane A) ✅

P3 as a gate: a symbol command changes its own object's lines and nothing else.
The harness is M1's `changed_line_count`; this task turns it into a per-command
assertion.

- **Check:** `cargo test a_symbol_command_changes_only_its_own_lines` — for each
  of move, rotate, mirror, delete: the changed line count is within the
  documented bound for that command, and every other line of the file is
  byte-identical.

### T9 — `sym set-field`, instance-aware (Lane B) ✅

Setting `Reference` is the case the format punishes. The truth is
`instances → project → path → reference`, and the `property` on the symbol is a
cache of whichever sheet was loaded last. Both must move together, and only the
matching path's entry may change.

- **Check:** `cargo test setting_a_reference_updates_the_path_that_was_asked_for`
  — on the twice-placed child sheet, setting the reference for one sheet path
  changes that path's entry and the cached property, and leaves the other path's
  entry alone.
- **Check:** `cargo test setting_a_value_touches_no_instance_data` — a field
  that is not `Reference` changes the property and nothing else.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test kicad_agrees_about_the_reference`
  — the netlist of the written file names the symbol as kicli says it did, on
  both sheet paths.

### T10 — `field move`, `field rotate`, `field justify` (Lane B) ✅

A field is movable text with its own position, angle and justification. Its
`(at …)` is absolute schematic space, so a move is a direct edit and needs no
transform. Every one of these clears `fields_autoplaced`.

Fields are exempt from the grid rule: KiCad's own autoplacement lands them on
arbitrary units, so snapping them would fight the editor.

- **Check:** `cargo test moving_a_field_clears_the_autoplace_flag` — for move,
  rotate and justify.
- **Check:** `cargo test a_field_is_not_snapped_to_the_grid` — a field placed at
  an off-grid position stays there and raises no finding.
- **Check:** `cargo test justification_survives_a_round_trip` — the nine
  justification pairs write and read back unchanged.

### T11 — `field show` and `field hide`, on every object that owns fields (Lane B) ✅

Not just symbols. A sheet owns `Sheetname` and `Sheetfile`; a global label owns
`Intersheetrefs`; a netclass flag owns `Netclass` and `Component Class`. This is
the parity requirement of Constitution §2, and the version gate matters: `hide`
sits inside `effects` below stamp 20251028 and beside `show_name` above it.

- **Check:** `cargo test hiding_a_field_writes_the_form_the_file_uses` — a v10
  file gets the current form, a v9 fixture gets the old one, and each re-parses
  as hidden.
- **Check:** `cargo test every_object_that_owns_fields_can_hide_one` — symbol,
  sheet, global label and netclass flag, one each.

### T12 — `text add|move|edit|delete` (Lane C) ✅

Free text and text boxes. A text box carries a size as well as a position, which
the item model does not yet hold — add it, since a box that cannot be resized is
not parity.

- **Check:** `cargo test text_survives_the_four_operations` — add, move, edit,
  delete in sequence leaves the file as it started, byte for byte.
- **Check:** `cargo test a_text_box_keeps_its_size` — a box added with a size
  re-parses with it, and a resize changes only the size.

### T13 — `label add|move|delete` (Lane C) ✅

Local, global and hierarchical labels. A label anchor is connectable geometry,
so it snaps to the grid. Adding a hierarchical label is the half of a sheet port
that lives in the child; the parent's sheet pin is M8's business, and the
command says so rather than half-doing it.

**A label on a wire's interior connects**, unless a pin or another label shares
its anchor. Adding one is therefore a connectivity change, and the mutation
report says which net it joined or created.

- **Check:** `cargo test adding_a_label_says_what_it_connected` — the report
  names the net the label joined, and the extractor agrees after the write.
- **Check:** `cargo test a_label_anchor_lands_on_the_grid`.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test kicad_agrees_about_the_new_net`
  — the netlist of the written file carries the net the report claimed.

### T14 — `junction add|delete`, with the four-way refusal (Lane D) ✅

A junction is what makes a crossing a connection. Adding one where four wire
ends already meet makes a four-way junction, which is the defect `KI-JCT-001`
scores and which KiCad's own check ignores by default. **Refuse it**, name the
four wires, and say that offsetting one by a grid step is the fix.

- **Check:** `cargo test a_four_way_junction_is_refused` — the refusal names the
  four wire ends, exits 1, and writes nothing.
- **Check:** `cargo test a_junction_joins_what_it_sits_on` — adding one at a
  mid-span pin joins the pin to the wire, which the extractor confirms, and
  deleting it separates them again.

### T15 — `noconnect add|delete` (Lane D) ✅

A no-connect marks a pin as deliberately unconnected. Adding one to a pin that
is connected is a contradiction: refuse it and say what the pin is joined to.

- **Check:** `cargo test a_no_connect_on_a_connected_pin_is_refused`.
- **Check:** `cargo test a_no_connect_lands_on_its_pin` — the marker is at the
  pin's connection point, on grid, and the invariants pass.

### T16 — `net rename`, as a relabel (Lane D) ✅

kicli does not write `.kicad_pro` in v1, so a net's name is only what its labels
say. Renaming a net renames its labels — every one of them, across every sheet
the net reaches, in one atomic write. A net with no label cannot be renamed:
say so, and say that `label add` is the way to name it.

A power net's name comes from its power symbols' `Value`, so renaming one is a
field edit on those symbols, and the command says which it changed.

- **Check:** `cargo test renaming_a_net_renames_every_label_it_has` — across two
  sheets, in one write, with the extractor agreeing afterwards.
- **Check:** `cargo test an_unnamed_net_cannot_be_renamed` — the refusal names
  the net's handle and points at `label add`.
- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test kicad_agrees_about_the_rename` —
  the netlist of the written file carries the new name and the same partition.

### T17 — The mutation fixture set (orchestrator, after the lanes)

Every lane needs a project it may write to. Tests copy a fixture to a scratch
directory and mutate the copy; the committed tree is never written by a test.
This task records that as a helper and asserts it: after the whole suite, the
fixture tree is byte-identical.

**The assertion half is done, and more generally than this task asked.**
`cargo xtask check` now compares the working tree before and after the run and
fails when they differ, so a test that writes anywhere outside `target/` breaks
the build by construction — not only one that writes a fixture. What is left is
the helper: seven test files carry their own `scratch`/`scratch_copy` copy of
the same six lines.

- **Check:** `cargo xtask check` reports the `clean` gate as passing, and the
  copy helper has one home rather than seven.

### T18 — Extractor parity: the pins that share a point (Lane E) ✅

The largest remaining class of corpus mismatch. On `CM5_MINIMA_3` kicli puts
`SW601.2`, `R601.1` and `TP701.1` on nets KiCad leaves them off, and splits
`U1.4` and `U1.6` off nets KiCad joins them to. Both shapes point at one rule
about what happens when several connectable things share a point.

Measure it the way the label rule was measured: build the smallest schematic
that shows the difference, ask `kicad-cli` what it thinks, and write the rule
down with its evidence before implementing it.

- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test --features corpus netlist_partition_matches_kicad_corpus`
  — the count of matching hierarchies rises, and the commit message names the
  demo that exposed the rule.
- **Check:** `cargo test` — a hermetic fixture carrying the new case, with the
  oracle beside it.

### T19 — Extractor parity: whatever is left (Lane E) ✅

The same loop for each remaining class, one commit each, each naming its demo
hierarchy. `research/notes/` gains a note per rule, as the pin and label rules
did.

- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test --features corpus netlist_partition_matches_kicad_corpus`
  — **35 of 35**. This gates M4. ✅ The test no longer carries an `ignore`.

**Done: 35 of 35, up from 22.** Two rules closed the lane's last class, and both
were measured before they were written:

1. Where one bus carries two bundle names, their corresponding members are one
   net. A group member corresponds by its own name, a vector member by its
   place in the range and not by the number in its name.
2. A bundle label names its members in the namespace of the sheet it is drawn
   on, so two bundles labelled on one sheet share the members whose names are
   equal, with no bus between them. A sheet pin names nothing on the sheet it
   is drawn on, because its name speaks for the child's namespace.

One measured shape is deliberately not reproduced: a bus carrying a vector
bundle against a plain group, which KiCad joins degenerately. kicli **reports**
it as the `mixed-bundle-kinds` warning rather than differing in silence, and
`no_corpus_hierarchy_mixes_bundle_kinds` asserts no demo draws one, so the claim
that it is degenerate is checked against real drawings rather than asserted.

Three probes in this lane measured their own defects before they measured
KiCad's: a sheet-pin angle that took a port off its bus, and coordinates written
at full floating-point precision that kicli's reader turned into zeros. Every
probe now carries a control that fails loudly, and `Probe::check_precision`
refuses to write a drawing carrying a number KiCad would not write.

**One defect found on the way is not fixed here and wants its own task:** a
coordinate the reader cannot parse becomes zero instead of an error.

### T24 — A refused number is never a zero ✅

Found while closing T19: `parse_iu` correctly refuses a value kicli cannot
represent exactly, and the caller read the refusal as a default. A zero
coordinate is not a refusal — it moves the item to the origin, joins it to
whatever else landed there, and reports a confident net list about a drawing
nobody drew. It cost this lane two false findings before it was caught, and on
a mutation path the same failure writes the move back as though it were meant.

- **Check:** `cargo test --test unreadable_numbers` — a file with an unreadable
  coordinate does not load, and the message carries the text and its offset. ✅
- **Check:** `cargo test --test measurements_are_never_defaulted` — no
  measurement read anywhere in the workspace falls back to a default. ✅
- **Check:** `cargo test --features corpus every_corpus_hierarchy_loads` — the
  refusal never falls on a drawing KiCad wrote. ✅

`Doc::check_measurements` refuses the file at the boundary, so no reader below
has to decide what an unreadable coordinate means. It takes the objects the
caller keeps verbatim: KiCad's `image` carries a placement and a scale at full
float precision that kicli copies rather than reads, and a first, broader
version of the check wrongly refused `jetson-agx-thor-baseboard` because of it.
Measuring the corpus rather than assuming is what found that — 963 files, and
`image` is the only object in any of them holding a value outside kicli's unit.

Clippy has no lint for defaulting a failed parse; `map_unwrap_or` and its family
are about style. The rule is executable instead, as Constitution §11 asks.

The audit of the workspace's other defaults found one more real masking:
`unit_of` read half a malformed library body name as unit 0, which means "drawn
by every unit", so one unit's pins would have gone onto all of them.

### T23 — What Eeschema does when its file changes underneath it (any lane, low priority)

Measurement, not code. kicli edits files on disk, and an editor holding the same
file is the obvious hazard. `spec/SPEC.md` §14.4 warns about it in words written
from assumption, which is not how anything else in this project is decided.

Find out what KiCad 10.0.5 actually does: whether Eeschema notices an external
change at all, what Revert does and what it discards, what happens when the
editor has unsaved changes of its own, and whether any prompt appears. Write it
up as a research note with the recipe, the way the pin and label rules were
written up.

The note feeds two things: `AGENT.md` gains guidance on working beside an open
editor, and §14.4's warning text is rewritten from what was measured.

Low priority: it blocks nothing. Any lane may take it when its own work is
waiting on a check.

- **Check:** `research/notes/eeschema-external-changes.md` exists, carries a
  reproduction recipe, and states each behaviour as measured or as not
  established. `AGENT.md` cites it, and §14.4's wording follows it.

Wire every verb into `cli`, with `--output json` carrying the mutation result.

While the surface is open: `project info` still prints "kicli does not extract
nets in this build", which stopped being true when the extractor merged. Fix it

- **Check:** `cargo test agent_doc_covers_every_command` — the M2 test, now
  covering the mutation verbs. ✅
- **Check:** `cargo test --test command_surface` — every verb parses, and every
  refusal exits with the code its table row names. ✅

**Done before the surface itself:**

- `project info` reports the net count instead of "kicli does not extract nets
  in this build", with any partition warning beside the count it qualifies.
  Both goldens refreshed for that and nothing else.
- The cached-field audit. The unit a symbol draws is a property of the sheet
  path, and `Symbol::drawn_on` is now its one home, beside `reference_on` where

**The surface: 26 verbs across nine nouns.** `sym place|move|rotate|mirror|
delete|set-field`, `field move|rotate|justify|show|hide`, `text add|move|edit|
delete`, `label add|move|delete`, `junction add|delete`, `noconnect add|delete`
and `net rename`, beside the three read verbs M2 shipped. Every one of them
opens the project, resolves `--sheet` to one placement, hands the change to
`edit`, and prints the mutation result with its four invariant outcomes.

Three decisions the surface made, recorded so they are not re-argued:

1. **An object is addressed by reference designator or by identifier**, whole or
   by the eight characters a view prints. Eight do not always identify, so a
   prefix that names two objects is refused with both listed. A reference
   designator resolves on the sheet path being edited, never on the cache.
2. **`sym place` takes its definition from `--from <FILE>` or from a copy the
   project already embeds.** kicli does not search the library tables in this
   build, and the refusal says so rather than writing a placement that draws as
   a placeholder. Library resolution is `M7`'s.
3. **`text edit` takes one of `--text` and `--size`.** One command is one write
   and one delta, so changing both is two runs.

**One thing SPEC §6 lists that this does not wire: `sch view --view delta`.**
See the note below; it is parked for James rather than decided here.

### T22 — The whole loop, end to end ✅

One test that does what an agent does: read a view, make three edits, read the
delta, and check the file against KiCad. It is the only test that proves the
milestone rather than a task.

- **Check:** `KICLI_TEST_KICAD_CLI=1 cargo test --test mutation_loop` — place a
  symbol, move a field, add a label; the views change as predicted; the delta
  names exactly those objects; `kicad-cli` reads the result without a new fault;
  and the round-trip properties still hold. ✅

The test drives the compiled binary and reads the JSON each command returned, so
the report and the file cannot drift apart. Each delta names exactly one object.
"No new fault" is measured as the items KiCad's rule check reports that do not
name the placed symbol, before and after, which is the only form of the claim
that is true: placing an unconnected symbol adds findings of its own, and they
are the point rather than a regression. The comparison carries its control — the
report parser must have read items from the drawing as it stood, or "nothing
else moved" would be true and empty.

## BLOCKED — awaiting James

### The delta view, and what `@last-write` can answer

`spec/SPEC.md` §6 lists `sch view --view connectivity|layout|delta`, and §7.3
makes the delta one of the three first-class representations. T5 settled the
snapshot file format for M3 and every mutation now writes `@last-write`. No
command reads it.

Wiring `--view delta` needs one decision, and the two governing statements do
not agree on it:

- **T5:** "Every mutation updates the implicit `@last-write` snapshot under
  `.kicli/`, so **the next command can answer 'what did my last command
  changed?'** without bookkeeping." Under that reading, a delta printed after a
  mutation should list that mutation's objects.
- **`model::mutate::commit`, as M3 built it and as T5's own check
  `the_last_write_snapshot_follows_every_mutation` asserts:** `@last-write`
  holds the state **after** the write, and is the *before* state that the *next*
  mutation compares against. Under that reading, `Delta::between(@last-write,
  the file now)` is empty immediately after any kicli mutation, and is non-empty
  only when something else — Eeschema, a person, another tool — changed the file
  since. That is a useful view, and it is not the one T5's sentence describes.

Both readings are defensible and they produce different commands. kicli does not
pick one here. Two ways out, for James to choose:

1. `sch view --view delta` means "what has changed since kicli last wrote", and
   T5's sentence in `tasks/M3.md` is corrected to say so. This is the reading the
   code already implements and it needs no second snapshot.
2. `commit` keeps a second snapshot — the state *before* the write, under a name
   of its own — and `--view delta` reads that. This matches T5's sentence and
   costs one more file per project under `.kicli/`.

Nothing else in M3 depends on the answer. Every mutation already reports its own
delta fragment, so an agent doing look → edit → verify is not blocked by this.

### The on-grid invariant does not check symbol pins

T3's check text names "a pin moved off grid" as one of its four planted faults.
The fault the test plants is an off-grid **junction**, and
`invariant::geometry_on_grid` reads wires, junctions, no-connects, bus entries,
labels and sheet pins — never a symbol's resolved pins. Its own doc comment says
"Pins, wire ends, junctions, no-connects and label anchors", so the comment and
the code disagree.

The behaviour may well be right. Constitution §7 and `spec/SPEC.md` §8 both call
an off-grid pin a **lint** finding, and `--off-grid` is documented as overriding
the snap and raising a finding — not as a write kicli refuses. Making the
invariant check pins would make `sym move --off-grid` fail with exit 3 for any
symbol that has pins, which would make the flag useless.

So this is one of: a doc comment that overstates the invariant, or a check T3
never implemented. It is not resolved here because the answer changes whether a
documented flag keeps working.

## Milestone exit criteria

M3 is complete when all of the following pass on a clean checkout:

```sh
cargo xtask check
cargo test
cargo xtask corpus
cargo test --features corpus
KICLI_TEST_KICAD_CLI=1 cargo test --features corpus
```

with these gates green:

| Gate | Assertion |
|---|---|
| atomic write | a failed verify leaves the original byte-identical, with no temporary left |
| invariants | four planted faults, each caught by the invariant it belongs to |
| locality | every command changes only its own object's lines |
| instance awareness | a reference set on one sheet path leaves the other alone |
| autoplace flag | every field position kicli sets clears `fields_autoplaced` |
| refusals | four-way junction, no-connect on a connected pin, rename of an unnamed net |
| netlist oracle | **35 of 35 demo hierarchies** — this gates M4 |
| round trip | P1 and P2 hold on every fixture after every mutation |
| KiCad agrees | the rule check and the netlist of every written file match kicli's claims |

M3 ships the first commands that write. Nothing in it routes a wire.
